# 样本原图存档

生成页面前，**先按下方文件清单查对应原图并 Read**，再按 `../rules.md` 的参数实现。文字描述会漏细节，图不会。

## 命名与查图规则

- 单图样本：`S-XX.jpg`；同一多样本变体：`S-XXa.jpg` / `S-XXb.jpg`。
- **不要按 `S-XX.jpg` 猜路径**：例如 S-03 只有 `S-03b.jpg`，S-13 有 `S-13a.jpg` / `S-13b.jpg`。以本清单为准。
- 工作流 B 选定样本后，按 `SKILL.md` 步骤 2 查本清单；清单里没有的样本按 `rules.md` 的文字条目实现。
- 新投喂的图按同一规则命名，并补一行到本清单；规格统一为 582×1200（原投喂图 1152×2376 手机截图缩至半幅）。

## 为什么存这里

`rules.md` 的条目是参数化描述（色值、字号百分比、布局类型），写描述时看不见图，容易丢掉「这张到底为什么好看」的关键手法。2026-11 补档时对照 S-13 原图就发现：它的三行标题各自压着一块**白色实心底**，这个手法在规则条目里完全没写——只按描述做，出来就是「黄底黑字」而不是原图那种「一块块浮起来的字」。该手法现已补进 `rules.md` 的 S-13 条目与 `selection.md` 的签名元素列。

## 缺失

**S-01、S-02、S-05、S-06、S-07、S-08、S-09、S-10、S-11、S-12 没有原图**，只有 `rules.md` 的文字条目。这几条靠描述仍可复现（每条都带可抄 CSS，但需按 `baseline.md` 的单位约定换算），细节可能失真。用户若重新投喂，补进本目录并登记上表即可。

## 对照时看什么

1. **签名元素**长什么样、占多大面积、压在哪
2. 色块是**实心还是半透明**、边缘是否出血
3. 大字与色块的关系（压在块上 / 破出块外 / 块贴着字走）
4. 留白的**形状**（是整块空，还是被元素切成几条通道）
5. 字重与字距的实际观感，对照条目里的百分比是否需要微调
